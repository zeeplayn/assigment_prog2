## Книга 1 (Price) — Chapter 3 "Controlling Flow, Converting Types, and Handling Exceptions" (стр. 134–168)

### Exercise 3.1 — Test your knowledge

1. **Деление int на 0** — выбрасывается исключение `DivideByZeroException` во время выполнения.
2. **Деление double на 0** — исключения нет: результат `Infinity` (`double.PositiveInfinity`/`NegativeInfinity`), либо `NaN`, если делили `0.0 / 0.0` — так работает IEEE 754.
3. **Переполнение int** — по умолчанию (в unchecked-контексте) значение молча "перескакивает" через границу диапазона (wraps around) без исключения; в `checked`-контексте вместо этого выбрасывается `OverflowException`.
4. **x = y++ vs x = ++y** — `y++` (постфиксный) — сначала x получает старое значение y, потом y увеличивается; `++y` (префиксный) — y увеличивается сначала, x получает уже новое значение.
5. **break vs continue vs return в цикле** — `break` полностью прерывает цикл; `continue` пропускает оставшуюся часть текущей итерации и переходит к следующей; `return` завершает выполнение всего метода целиком (не только цикл).
6. **Три части for** — инициализатор; условие; итератор (шаг). Обязательны только точки с запятой между ними — сами части могут быть пустыми.
7. **`=` vs `==`** — `=` — оператор присваивания; `==` — оператор сравнения на равенство.
8. **`for ( ; ; ) ;`** — да, компилируется: это бесконечный цикл (все три части опущены) с пустым телом-инструкцией (`;`).
9. **`_` в switch-выражении** — это discard-паттерн, "поймать всё остальное" — срабатывает, если ни один из предыдущих вариантов не подошёл (аналог `default`).
10. **Интерфейс для foreach** — объект должен реализовывать `IEnumerable` (или `IEnumerable<T>`).

### Exercise 3.2 — Explore loops and overflow

Код `for (byte i = 0; i < max; i++)` с `max = 500` **зависает в бесконечном цикле**: `byte` умещает только 0–255, и при обычном (unchecked) сложении `i++` после 255 молча "перескакивает" обратно в 0 — условие `i < 500` никогда не станет ложным. Чтобы вместо тихого зависания получить явную ошибку, нужно обернуть инкремент в блок `checked` — тогда при попытке выйти за границы `byte` будет выброшено `OverflowException`, и программа корректно остановится с понятным сообщением (реализовано в `ControlFlowExercise.cs`).

### Exercise 3.3 — Test your knowledge of operators

1. `x = 3; y = 2 + ++x;` → `++x` выполняется первым: x становится 4, затем y = 2+4. **x=4, y=6**.
2. `x = 3 << 2;` → 3 (`011`) сдвинуть влево на 2 = `1100` = **12**. `y = 10 >> 1;` → 10 (`1010`) сдвинуть вправо на 1 = `0101` = **5**.
3. `x = 10 & 8;` → `1010 & 1000` = `1000` = **8**. `y = 10 | 7;` → `1010 | 0111` = `1111` = **15**.

## Книга 1 (Price) — Chapter 4 "Writing, Debugging, and Testing Functions" (стр. 169–228)

### Exercise 4.1 — Test your knowledge

1. **`void`** — ключевое слово означает, что метод не возвращает значение.
2. **Императивный vs функциональный стиль** — императивный описывает пошагово *как* делать (операторы, циклы, изменяемое состояние); функциональный описывает *что* нужно получить через выражения и композицию функций, отдавая предпочтение неизменяемости и чистым функциям.
3. **F5 / Ctrl(Cmd)+F5 / Shift+F5 / Ctrl(Cmd)+Shift+F5** — F5 = запуск с отладчиком (остановка на breakpoint'ах); Ctrl/Cmd+F5 = запуск без отладчика (быстрее, без остановок); Shift+F5 = остановить отладку; Ctrl/Cmd+Shift+F5 = перезапустить текущую отладочную сессию.
4. **`Trace.WriteLine`** — пишет в любые зарегистрированные trace listener'ы; по умолчанию в Visual Studio это окно Output/Debug, но можно настроить вывод в файл, журнал событий и т.д.
5. **Пять уровней трассировки** (`System.Diagnostics.TraceLevel`) — Off, Error, Warning, Info, Verbose.
6. **Debug vs Trace класс** — вызовы `Debug` выполняются только в Debug-сборке (вырезаются в Release); вызовы `Trace` выполняются и в Debug, и в Release (полезно для диагностики в продакшене).
7. **Три "A" юнит-теста** — Arrange, Act, Assert.
8. **Атрибут xUnit** — `[Fact]` (для теста без параметров) или `[Theory]` (для параметризованного теста).
9. **Команда запуска тестов** — `dotnet test`.
10. **Перебросить исключение без потери stack trace** — просто `throw;` (без указания переменной `ex`).
